# A1 反手 v4：单向挥拍与安全回球奖励

日期：2026-08-06

## 1. 为什么需要 v4

同一组 MuJoCo 发球、互换 v2/v3 predictor 的交叉回放证明，异常动作跟随
v3 actor，而不跟随 predictor：

| policy / predictor | 早期前伸 | 临击前回撤 | 再次前挥 |
|---|---:|---:|---:|
| v2 / v2 | 0.096 m | 无 | 无二次挥拍 |
| v2 / v3 | 0.098 m | 无 | 无二次挥拍 |
| v3 / v3 | 0.217 m | 0.149 m | 0.067 m |
| v3 / v2 | 0.231 m | 0.159 m | 0.051 m |

训练末段也表现为 v3 更容易碰球、但命中后的质量更差：hit rate
`85.2% -> 88.6%`，success rate `65.6% -> 61.0%`，success/hit
`77.0% -> 68.8%`；与此同时 `future_dis_ee` 增加 44%，action L2
增加 17%，action rate 增加 8.6%，而 swing-through 下降 21%。

根因是 v2/v3 从第一帧有效相机观测开始就用完整三维拦截距离奖励拉动球拍，
但接触时又要求正 x 方向速度。稳定的真实击球面目标使策略可以先前伸到目标附近，
再回撤制造挥拍行程，最后二次前挥。predictor 的真实击球面误差只有
y `4.6/10.5 mm`、z `9.8/23.4 mm`（MAE/P95），不是本次主因。

## 2. v4 奖励契约

v4 从零训练，继承 v3 的机器人、相机和执行器契约；改动限定在 A1-v4
的挥拍时序、回球结果语义、实测发球先验和球自转接触鲁棒性：

1. y/z 拦截定位仍可提前进行；x 方向定位只在预计触球前最后 `0.45 s`
   线性开放，早期保留 `0.10` 的弱跟踪，避免策略改成过深后撤再猛冲。
2. 距触球大于 `0.45 s` 时，球拍至少保留 `0.12 m` 前向行程；该约束在
   `0.60 -> 0.45 s` 平滑释放，权重 `-2`。
3. 最后 `0.45 s` 内惩罚负 x 球拍速度，权重 `-1`，抑制临击回撤而不限制
   正常前挥。
4. 落点目标从旧 `(1.15, 0)`、`3 m` 宽容阈值改为对方半台中心附近
   `(0.70, 0)`。使用平移高斯核
   `2*exp(-ln(2)*(d/0.50)^2)-1`：中心 `+1`、50 cm 边界为 0、远处
   平滑趋近 `-1`，权重 `100`。正负分统一乘首触质量，不制造“低质量
   击中只有 +25、打飞仍 -100”的避球动机。
5. 过网高度核宽从 `0.40 m` 收紧到 `0.20 m`，目标高度仍为 `1.11 m`。
6. 首触横向扫拍设置 `0.30 m/s` 死区，之后在 `0.70 m/s` 内平方增长，
   权重 `-20`。速度改为真实拍心速度 `v_body + omega x offset`，腕部旋转
   不能再绕过惩罚。
7. 首触时锁存碰前球速、拍面和拍心速度。拍面方向奖励只比较水平投影，
   权重从 `8` 提高到 `20`；竖直俯仰交给过网/落点目标，避免把上升来球
   机械地反射向下。
8. 几何首触不再立刻消耗落点/过网奖励。检测到真实 `vx>0.05 m/s` 出球后
   才结算；未形成回球则最多等待 `60 ms` 后按失败出射状态结算。
9. v1--v3 保留原落点投影；v4 把重复硬编码的 `Cd=.47,m=2.7 g`
   (`k≈.134`) 改为实际 Aero/球资产 `Cd=.4378,m=3.4 g`
   (`k=.0991089`)。旧模型会把阻力高估约 35%，典型横向落点偏约 8--9 cm。
10. v4 加入真实三维角速度，但只在本方桌物理反弹后注入，Magnus 保持 0。
    这样先覆盖旋转球的球拍接触 gap，同时不破坏当前无旋 preflight/击球面。

实现集中在：

- `legged_lab/physics/a1_backhand_v4_contract.py`
- `legged_lab/physics/swing_timing.py`
- `legged_lab/physics/landing_target.py`
- `legged_lab/mdp/rewards.py` 中的 `reward_a1_*` / v4 penalty 函数
- task `a1_tt_backhand_v4` 与 `a1_tt_backhand_v4_eval`

历史 v1-v3 的 reward term、函数和参数保持不变。

## 3. 发球与真实轨迹先验

`competitive_robot_table_tennis` 含 15,792 条真实击球后的单帧初始状态，
不是连续视频轨迹：2,704 serve、13,088 rally，每条含位置、线速度和角速度。
数据来自 Google DeepMind 的 *Competitive Robot Table Tennis: Initial Ball
States*，与论文 *Achieving Human Level Competitive Robot Table Tennis*
（ICRA 2025）一同发布；数据材料按 CC-BY-4.0 使用，筛选脚本按源仓库
Apache-2.0 条款参考其 MuJoCo 回放模型。这里保留署名、源 JSON SHA256 和筛选参数，
不把兄弟目录当成训练时的隐式依赖。
坐标到 A1 的右手旋转为：

```text
p_a1 = [p_y, -p_x, p_z + 0.76]
v_a1 = [v_y, -v_x, v_z]
w_a1 = [w_y, -w_x, w_z]
```

用数据仓库自带的 MuJoCo 接触/流体模型逐条 1 ms 回放，再依次要求朝向 A1、
过网球心不低于 `0.945 m`、接球侧落台、穿过 `x=-1.243 m`、交点在
`y=[-.22,.26] m,z=[.88,1.32] m,|vx|=[1,5.8] m/s`，最终得到
4,813 条：945 serve、3,868 rally。按 source ID 连续切分后，serve 的
train/validation/test 为 `756/94/95`，rally 为 `3094/387/387`；避免同一来源
的近邻样本随机散落到不同集合。源 JSON SHA256 分别为
`258179a5...e9a81ad`（serve）和 `300f4bf1...e0e1237`（rally）。复现入口：

```bash
/home/woan/.conda/envs/g1tt_sim2sim/bin/python \
  -m legged_lab.scripts.analyze_competitive_ball_states \
  --dataset-root ../competitive_robot_table_tennis \
  --output logs/dataset_analysis/a1_backhand_playable_20260806.json
```

当前版本没有直接重放全部状态，原因有两个：source serve 带合法的网前首跳，
而现有 sampler 是过网后单跳语义；完整 spin + Magnus 会使击球面交点相对无旋
模型偏移中位约 `7.2 cm`、P95 `26.5 cm`。v4 先从过滤后的 945 条 serve
拟合 32 个带权三维 spin 簇，保留轴间相关性；easy/hard 自转尺度
`0.5 -> 1.0`，幅值抖动 `±15%`，并在本方桌反弹后注入。后续版本再做
spin-aware preflight/Magnus A/B，不能把真值角速度作为真机 predictor 输入。

v4 hard 发球采用主分布 `bounce_x=[-.95,-.75], launch_vz=[1.2,2.3]`，
另有 45% 候选慢球尾部；解析 rejection 后尾部约占 10.5%。500 条 Isaac
物理交点为：

| 分位数 | y (m) | z (m) | abs(vx) (m/s) |
|---|---:|---:|---:|
| P5 | -0.164 | 1.030 | 1.546 |
| P50 | 0.022 | 1.086 | 2.286 |
| P95 | 0.217 | 1.176 | 3.268 |

实机 142 条的中位/P95 为 `z=1.097/1.166 m`、`|vx|=2.352/3.260 m/s`，
主区间已经对齐；解析 preflight 的速度分位数不能替代 PhysX 探针。

## 4. 物理参数定案

### 暂不修改 `tau_s`

训练与部署继续使用
`[0.10,0.10,0.08,0.10,0.05,0.05,0.10] s`。真机逐 tick 重算低通
残差约 `1e-16`，说明实现已经对齐。r4 的真机滞后约 `60 ms`、跟踪误差
P95 约 `0.108 rad`，且约 12.8% 样本接近 8 Nm 边界；减小 r4 `tau_s`
更可能增加饱和和欠阻尼。v3 的 r4 acceleration envelope 在 DR 回放中
p95 仅激活 1.70%，也不是双动作根因。

### 桌球摩擦保持 0.10；拍球摩擦暂不猜

外部数据库自带的系统辨识 MuJoCo 模型同样使用桌球切向摩擦 `0.10`；500 条
serve 回放的等效回复中位约 `0.959`、水平速度损失中位约 `0.551 m/s`，
支持当前桌球 `e=.95, mu=.10`，不应把桌球摩擦整体抬高。

当前有效球拍摩擦也被球材质的 `0.10` 限住，字面上可能低于真实胶皮，
但现有 29 条拟合、
7 条跨日验证接触不能辨识唯一 Coulomb 摩擦。固定其他参数后，`mu=0.10`
改为 `0.35` 的 held-out 改善不足 1%；`mu=0.35--0.70` 基本不可区分。
数据库没有球拍模型，也不能为拍球摩擦背书；此外 PhysX `combine=min` 会使
只提高球拍材质摩擦成为 no-op。

因此 v4 继续固定球拍回复 `0.75`、有效摩擦 `0.10`，不做宽回复或摩擦
DR，也不把 MuJoCo 刚度直接抄给 PhysX。后续先把桌球与拍球材质解耦，再做
`mu=0.10/0.35` A/B，并在更多带球自转的接触数据上拟合切向/旋转残差。

### 其余保持

- 相机延迟混合继续为 `15/75/10%`，主带 `45--80 ms`；真机稳定段中位
  总年龄约 `53.6 ms`、P95 `55.9 ms`。
- v3 的逐关节 fn/zeta/gain/delay DR 与 r4 acceleration envelope 保持。
- 回复系数：球/桌 `0.95`，球拍 `0.75`。
- predictor 保持 `5` 帧位置输入与 `64x64` MLP。真机没有可直接测得的 spin，
  扩宽网络不能解决隐藏变量不可辨识；先看 spin-on 的因果交点 MAE/P95，只有
  容量型欠拟合证据出现时才扩容或加历史，不改部署输入结构。

## 5. 已完成验证

- 纯逻辑、spin prior、接触事件、predictor 与发球回归测试：17 项通过。
- 20 万候选的 v4 CPU serve verifier 通过；解析 hard accepted tail `10.54%`。
- 500 条 Isaac hard 物理交点已按上表核验；全部过网硬约束成立。
- v4：2 个环境、1 个迭代的 Isaac headless 冒烟训练通过，reward manager
  读回了全部 v4 函数、参数和权重。
- v3：相同冒烟测试通过；导出的 env YAML 中没有任何 v4 term，确认历史
  配置仍为 spin/outcome OFF、旧 landing-k、旧方向奖励权重 8。
- 用 v3 `model_18100` 在 v4 环境做有限步事件探针，4 次真实出球的几何首触到
  出射确认延迟为 `8--14 ms`，`negative_vx_fraction=0`、timeout=0；spin
  反弹后注入也逐球触发。
- 旧 v2/v3 MuJoCo trace 反算：新 late-backtrack 项对 v3 的累计触发约为
  v2 的 2.4 倍；early-forward 项只在 v3 明显触发。

## 6. 正式训练验收

v4 仍为 scratch `5k easy + 10k ramp + 5k hold`，禁止 warm-start。正式启动后：

1. 3k--5k 先看 `penalty_early_paddle_forward`、
   `penalty_late_paddle_backtrack`、固定发球 paddle-x 时序，确认没有换一种
   方式 farm 新奖励。
2. 同时看 hit、success、success/hit、swing-through、action rate；目标不是
   单纯提高训练 reward，而是恢复命中后的上台转化率。
3. predictor 继续监控真实击球面 MAE/P95；若超过当前毫米级基线才预警。
4. 开训探针必须确认 outcome 事件的 `negative_vx_fraction=0`，并同时记录
   predicted/actual landing MAE、50 cm 圆内假阳性率和真实过网高度。
5. 5k/15k/20k 依次做 play、hard eval、MuJoCo sim2sim 交叉筛选；未经这些
   实测不因训练 shaped reward 宣布成功。

云端 v3 在本次改动期间保持运行，未停止、未重启、未覆盖任何成果。
